# Jira 工時紀錄

以繁體中文協助使用者省事地記錄每日或每週工作時數。使用者接受合理估算與分散填寫，不要求詳細日誌或精確湊滿 7 小時。

## 時數與分配原則

- **一天約 7 小時包含會議、學習與議題工作**，不是每張單或 Jira 議題工作每天都要填 7 小時。以實際投入為準，接近即可；不要為補滿時數編造工作。
- **會議時間排除於本次 Jira 登錄**，只在每日摘要列出扣除量，不自動記到開發、學習或會議單。
- **學習時間屬於當日總量**。針對某張單的必要研究可記在該單；獨立學習若已有明確的學習單就記該單，否則另列並扣除，不攤到無關的單。避免把同段時間同時算成研究與學習。
- 預設使用 0.5 或 1 小時粒度，必要時可更細。會議與學習扣除量不必為了取整而改動；分配後的總量可以略低於參考值。已有明確時數時保留它，不強行改成 7 小時。
- 按當期投入比重分散到本人處理的單，主要工作分較多、次要工作分較少。可集中在一張或分到數張，不要求平均分配，也不讓每張待辦單都分到工時。
- 備註一句即可，例如「需求分析與實作」「問題修正與驗證」「測試與調整」「技術研究」。描述應符合已知活動，不宣稱未確認的完成、上線或驗收。

## 取得日期、會議與候選單

1. 使用 `Asia/Taipei` 時區。每日未指定日期時用今天；每週未指定週期時用本週一至今天。只處理已實際工作的日期，排除已知假日、週末與請假；使用者有說明加班則依說明處理。半天或今天尚未結束時，依已投入時間調整，不預填未來工時。
2. 沿用對話中的 Jira 網站與本人身分；必要時用 Atlassian 連接器取得可存取網站、目前使用者與 accountId。多個網站且無法判定目標時再問，不以顯示名稱猜人。
3. 會議優先採用使用者提供的每日／每週時數，或已連接行事曆中當期實際參與的會議。取消、拒絕、個人提醒與非會議事件不扣除；重疊會議用聯集計算，只算一次，已知只參加部分就只扣該段。只有整週會議總量時可按工作日粗分，標示估算。無法取得時一次詢問「這段期間會議、獨立學習與請假各大約多少？」；未知不能默認為零。等待期間先查單與既有工時。
4. 用明確的 **JQL** 找候選單，取完整分頁：

   ```jql
   assignee = currentUser() AND statusCategory != Done ORDER BY updated DESC
   ```

   補登過去期間也要納入當期已完成或之後轉派的單：結合期間內的本人活動、已知 Jira key 與 assignee 歷史查詢，避免只看今天仍未完成的單。使用者指定的單優先，但先確認其與本次工作相關。
5. 讀取必要的摘要、狀態、指派與活動資訊，結合本對話工作、進行中議題、使用者的簡短說明，判斷粗略投入比重。不要求逐分鐘證據；僅被指派、他人更新或自動化更新不能單獨證明本人已投入。資訊不足以合理分配時，列候選單並一次詢問當期主要處理哪幾張；能確定的部分繼續整理。

## 先檢查已有工時，再補缺口

- 查本人在該期間已記錄的 worklog，涵蓋已完成、已轉派與其他專案的單，不只查目前候選單。可用下列 **JQL** 找有既有紀錄的單，再讀明細：

  ```jql
  worklogAuthor = currentUser() AND worklogDate >= "YYYY-MM-DD" AND worklogDate < "YYYY-MM-DD"
  ```

  第二個日期用期間結束日的隔天。JQL 僅找候選議題，明細仍須依 `author.accountId` 與轉成台北時區後的 `started` 篩出本人的期間內紀錄；Jira 網站時區不同或未知時，查詢邊界向前後各放寬一天，再依明細精確篩日期。
- 用 `executeRead` 執行 `listJiraIssueWorklogs`（可帶 `startedAfter`／`startedBefore` 毫秒時間戳縮小範圍）讀明細；比較明細筆數與 `total`，不足就以 `startAt` 讀完分頁。不能確定是否已有工時時保留草稿，不猜零、不重複新增。
- 每日先分清「會議」「獨立學習／其他時間」「議題工作」，每段時間只歸一類。議題可補時數約為：

  ```text
  max(0, 當日參考總量 − 會議 − 獨立學習與其他已占用時間 − 已記錄的議題工作)
  ```

  已記在學習單的時數屬於獨立學習，不再扣成議題工作；尚未登錄的獨立學習可另外補到其專用單。研究若算在議題工作裡，就不再列獨立學習。既有會議 worklog 保持原樣，不再新增或重扣。
- 7 小時是分配參考，不是必補的缺額。已有工時足夠、整天休假或可分配量為零就跳過；不足但沒有相應工作可記也不硬補。已有總量超過參考值不自動減少紀錄。
- 同一日期與同一議題預設合併為一筆新工時；已存在同日紀錄時只補可確認未記的部分，不覆蓋。只有使用者明確要求修正時才更新指定的 `worklogId`。

## 草稿與實際寫入

- 使用者說「建議怎麼填」「先給草稿」或只在設計此 skill 時，僅產出草稿。
- 使用者明確說「填寫」「補登」或「幫我記到 Jira」，且日期、單與扣除量已足以決定時，先簡短展示分配表，再直接寫入；不用重複要求已給過的授權。缺少必要資訊時只問缺少的部分。
- 使用 Atlassian MCP 的 `executeWrite`，`name: "addOrEditJiraIssueWorklog"`，`cloudId` 放在頂層、其餘參數放在 `inputs`：
  - `cloudId`、`issueIdOrKey` 使用已確認的網站與議題。
  - `timeSpent` 用 `2h`、`1h 30m` 等明確時數，不用 `d`，避免 Jira 每日工時設定與本 skill 的 7 小時參考混淆。
  - **每筆都明確傳入 `started`**，例如 `2026-10-12T09:00:00.000+0800`；補週工時仍逐日記錄，不能全部落在今天。優先用已知開始時間；只有日期時用同日合理的記帳時間並標示估算，不使用未來時間。
  - `comment` 一句簡短備註，`contentFormat: "markdown"`；新增時不帶 `worklogId`。
- 寫入逐筆處理並保留回傳的 worklog ID。成功後核對日期、作者與秒數；失敗就回報成功／失敗的明細。逾時或結果不明先重查，確認未建立才重試一次；仍無法確認就停止該筆，避免重複記錄。
- 本次只處理 worklog，不額外建立 Jira 單或修改狀態、指派人與工時預估。此 skill 支援每天或每週被呼叫，不自行建立排程。

## 回覆格式

使用一張簡短表：`日期｜Jira 單｜時數｜簡短備註｜草稿／已登錄／失敗`。附每日或整週的議題工時、獨立學習與排除會議總量；有未分配或估算部分才加一句原因，不展開詳細工作日誌。

例如一天約 7 小時、會議 1 小時、獨立學習 0.5 小時，議題工作可粗分為 A 單 3 小時、B 單 2.5 小時。若已有 A 單 2 小時，則僅補 A 單 1 小時與 B 單 2.5 小時；學習有專用單才另補 0.5 小時。不要再新增 5.5 小時議題工時。
